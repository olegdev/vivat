# VIVAT — перенос вёрстки в PHP / Blade

Это статический прототип сайта, собранный по макету Figma. Здесь описано, во
что превращается каждая его часть при переносе в Blade-шаблоны.

Прототип не «примерная вёрстка, которую надо переделать» — это разметка,
выверенная по макету на трёх ширинах (1440, 768 и 360). Задача переноса —
сохранить её, заменив мок-данные серверными.

---

## 1. Как запустить

Нужен любой веб-сервер: страницы подключают ES-модули, а они не работают по
`file://` — браузер блокирует их CORS-политикой. Двойной клик по HTML покажет
страницу без стилей и без поведения.

```bash
php -S localhost:8000 -t .        # из этой папки
# или
npx serve .
```

Дальше открыть <http://localhost:8000/index.html> — это список всех экранов.

Каждая страница — один адаптивный DOM. Мобильная версия выражена утилитами
`max-md:` (и планшетная — `max-xl:`) прямо в разметке, отдельных мобильных

Две страницы существуют в обеих половинах и в бою становятся **одним
маршрутом** — каталог и карточка товара. Дилерский вариант отличается от
покупательского только обвязкой и ценами, и всё это выражено через `data-user`
на `<body>` (раздел 8). Скрипты у пар разные ровно потому, что прототип не
знает, кто смотрит; в Blade это один шаблон и одна проводка.

## 2. Структура папки

```
index.html               список всех экранов
pages/customer/*.html    страницы: сюда уже вклеены все партиалы
pages/dealer/*.html
pages/*/*.js             скрипт страницы — только проводка, без данных и без разметки
partials/*.html          общие блоки (55) → resources/views/partials/*.blade.php
components/*.js          поведение (карусели, дроверы, жесты, карта, окна)
data/*.js                МОК-ДАННЫЕ → заменить серверными
styles/app.css           скомпилированный Tailwind (см. раздел 7)
assets/                  картинки и видео
assets/fonts/            Onest — вариативный woff2 (100–900) в четырёх подмножествах + OFL.txt
```

Шрифт подключает `partials/fonts.html` — один `<style>` с четырьмя
`@font-face`, ничего с Google Fonts не грузится. В Blade это
`@include('partials.fonts')` в `<head>`, а пути в `url()` — через
`asset('assets/fonts/…')`. Файлы — те же, что раздаёт Google (Onest v2.001),
лицензия OFL лежит рядом.

Структура повторяет исходный репозиторий вёрстки один в один, поэтому путь в
этой папке — это путь в проекте вёрстки. Один файл здесь сгенерирован сборкой:
`components/promo-coral-svg.js` — SVG коралловой промо-плитки, который прототип
импортировал через Vite (`?raw`). В Blade вставьте SVG прямо в партиал и
удалите файл; в его шапке это написано.

## 3. Разметка страницы: маркеры `@include`

Общие блоки лежат в `partials/`, но в страницу они **вклеены**, чтобы её можно
было открыть и увидеть целиком. Каждая вклейка обёрнута маркером, который прямо
называет нужную директиву:

```html
<!-- @include('partials.header') ▼ источник: partials/header.html -->
    …разметка шапки…
<!-- ▲ /@include('partials.header') -->
```

Перенос механический: удалить всё между маркерами, вставить строку из маркера.
Файл `partials/header.html` при этом становится
`resources/views/partials/header.blade.php` без изменений.

Маркеры вложенные — партиал может включать другой партиал. `partials/modals.html`
— целиком такой «хаб»: он состоит из включений девяти окон (заявка, «отправлено»,
вход, доступ к оптовым ценам, подписка, письмо директору, «О нас», «Поделиться», сообщение об ошибке),
и страница одной строкой монтирует все — окна принадлежат не странице, а
шапке, подвалу и меню, поэтому их несёт каждая.

**Партиал, который две страницы показывают с разным текстом, берёт параметры, а
не копируется.** `partials/stores.html` — это и блок «Наши салоны» на главной, и
«Где купить» на карточке товара, и шаг выбора магазина в заказе, и карта на
Контактах: заголовок и лид несут хуки `data-stores-title` / `data-stores-desc`,
которые переопределяются с места вызова. Так же устроен `seo-kitchens.html`
(`data-seo-title`). В Blade это `@include('partials.stores', ['title' => …])`.

**Оболочка раздела «Для бизнеса» — не партиал.** Одиннадцать контентных
страниц дилерской половины держат одну и ту же обёртку — заголовок «Для
бизнеса», боковое `menu-b2b` (298px) слева и колонка содержимого справа, — но
она написана в каждой странице руками: включение здесь плоская вклейка, обернуть
тело страницы оно не умеет. В Blade это очевидный `@extends('layouts.b2b')` с
одним `@section('content')` — заведите его и снимите обёртку с каждой
страницы.

## 4. Списки: `<template>` → `@foreach`

Всё, что повторяется — карточки товаров, промо-плитки, пункты меню, магазины,
группы фильтров, строки таблиц и деревьев документов — устроено одинаково:

* **единица списка** лежит как чистый `<template>` в партиале;
* скрипт клонирует её по разу на элемент данных и заполняет по `data-*`-хукам.

Это и есть будущий `@foreach`: тело шаблона — тело цикла, `data-*`-хуки — места
подстановки. Скрипты **никогда** не собирают разметку из строк, поэтому искать
HTML внутри JS не нужно: его там нет.

| Шаблон | Файл | Кто клонирует | Во что превращается |
|---|---|---|---|
| карточка товара (10 вариантов) | `partials/product-card.html` | `components/product-card.js` | `@foreach ($products as $p)` |
| карточка в сетке каталога | `partials/catalog-grid.html` | `components/catalog-listing.js` | `@foreach ($products as $p)` |
| секция-карусель | `partials/carousel-section.html` | `components/carousel.js` | `@include('partials.carousel-section', […])` |
| промо-плитка | `partials/promo-card.html` | `components/promo-card.js` | `@foreach ($promos as $promo)` |
| карточка отзыва | `partials/review-card.html` | `components/review-card.js` | `@foreach ($reviews as $r)` |
| карточка новости | `partials/news-card.html` | `components/news-card.js` | `@foreach ($news as $n)` |
| слайд героя | `partials/hero.html` | `components/hero-slider.js` | `@foreach ($slides as $slide)` |
| строка мега-меню | `partials/catalog-menu.html` | `components/catalog-menu.js` | вложенный `@foreach` |
| строка бургер-меню | `partials/mobile-menu.html` | `components/mobile-menu.js` | вложенный `@foreach` |
| пункт меню «Для бизнеса» | `partials/menu-b2b.html` | `components/menu-b2b.js` | вложенный `@foreach` (боковое меню и шторка — одни шаблоны) |
| карточка салона | `partials/stores.html` | `components/stores-map.js` | `@foreach ($stores as $s)` |
| город в селекторе | `partials/city-select.html` | `components/city-select.js` | `@foreach ($cities as $c)` |
| строка корзины | `partials/cart-card.html` | `components/order-cart.js` | `@foreach ($lines as $line)` |
| модуль в строке корзины | `partials/order-modules.html` | `components/order-modules.js` | вложенный `@foreach` |
| блоки характеристик | `partials/pdp-specs.html` | `components/pdp.js` | `@foreach` по группам |
| образцы цвета и сегменты сводки | `partials/pdp-summary.html`, `pdp-module-summary.html` | `components/pdp.js`, `pdp-module.js` | `@foreach ($swatches as $s)` |
| строка прайс-листа | `partials/price-mode.html` | `components/price-mode.js` | `@foreach ($modes as $m)` |
| подсказка и карточка поиска | `partials/search-overlay.html` | `components/search.js` | `@foreach` по выдаче |
| группа и документ дерева | `partials/doc-tree.html` | `components/doc-tree.js` | рекурсивный `@include` (глубина до 4) |
| блок и строка таблицы | `partials/data-table.html` | `components/data-table.js` | вложенный `@foreach` |
| плитка преимущества | `partials/benefit-tile.html` | `components/benefit-tile.js` | `@foreach ($benefits as $b)` |
| вопрос аккордеона | `partials/accordion.html` | `components/accordion.js` | `@foreach ($faq as $q)` |
| образец декора в фильтре | `partials/decor-filters.html` | `components/filters-panel.js` | `@foreach` |

Единица списка **не задаёт свою ширину** — её задаёт контейнер. Одна и та же
промо-плитка стоит и в ленте главной (`*:w-[437px]`), и в сетке «Акций». Не
переносите ширину внутрь шаблона.

## 5. JavaScript: что оставить, что выбросить

Скрипты делятся на три категории, и при переносе их надо развести. Делить нужно
**по функциям, а не по файлам** — в одном файле бывает и то, и другое.

**Оставить** — поведение, которого на сервере нет:

| Файл | Что делает |
|---|---|
| `components/carousel.js` | стрелки, перетаскивание, индикатор прокрутки, табы |
| `components/product-card.js` → `initProductCards`, `fillGallery` | галерея внутри карточки: свайп, наведение, точки |
| `components/hero-slider.js` | слайдер: стрелки, точки, свайп, звук по первому жесту |
| `components/catalog-menu.js`, `mobile-menu.js` | открытие/закрытие, переходы по уровням |
| `components/menu-b2b.js` | шторка раздела «Для бизнеса» ниже `md` |
| `components/search.js` | оверлей поиска, его состояния и подсказки |
| `components/modals.js` | открытие/закрытие девяти окон, Esc, клик по подложке, экран «отправлено»; у «Поделиться» и «О нас» формы нет |
| `components/pdp.js`, `pdp-module.js` | табы характеристик, лента фото, липкая панель цены, выбор образца |
| `components/stores-map.js` | Яндекс.Карты, пины, синхронизация со списком, четыре режима блока |
| `components/store-sheet.js` | шторка карты на мобильном (drag + прилипание) |
| `components/city-select.js` | выпадашка / лист выбора города |
| `components/catalog-listing.js`, `filters-panel.js` | ящик фильтров, чипсы, сортировка, запись параметров в адрес |
| `components/order-cart.js`, `order-modules.js`, `order-forms.js` | счётчик количества, пересчёт итога, раскрытие модулей, переключатель доставки |
| `components/price-mode.js` | панель прайс-листа и тумблер «Показать цену» |
| `components/doc-tree.js`, `data-table.js`, `accordion.js` | раскрытие групп, клиентский поиск по дереву, чередование строк |
| `components/scroll-lock.js` | **один** замок прокрутки на все девять оверлеев — считает владельцев, чтобы окно поверх бургера не снимало замок у меню |
| `components/phone-mask.js` | маска `+7 (___) ___-__-__` — один слушатель на `document`, разметке достаточно `type="tel"` |
| `components/consent-gate.js` | кнопка отправки неактивна без галочки согласия — по `input[name="consent"]` и `[type="submit"]` той же формы |

**Выбросить** — рендер списков, его заменяет `@foreach`: `renderCarousel`
(product-card.js), `renderPromoTiles`, `renderReviews`, и в каждом компоненте то
место, где он клонирует `<template>` по массиву данных. Туда же —
`components/disabled.js` (копит причины `disabled` от нескольких скриптов; на
сервере кнопку гасит рендер) и всё, что перечислено в разделе 9: `session.js`,
`partials/session.html`, `links.js` и атрибут `data-half`.

**Заменить на реальные запросы** — каждое такое место оформлено как «шов»:
одна функция, за которой стоит весь эффект, и в коде она помечена `SEAM` / `ШОВ`.
Контракт у всех уже задан разметкой: `data-product-id` на кнопке, имена полей в
форме фильтров, `endpoint` в конфиге карусели. Менять разметку под запрос не
нужно — только тело функции.

| Шов | Файл | Сейчас | Должно стать |
|---|---|---|---|
| фильтры каталога | `components/catalog-listing.js` → `applyFilters()` | фильтрует уже отрисованные карточки, пишет параметры в URL | `GET /catalog?…`, серверная выдача |
| фильтры декоров и 3D-моделей | `components/filters-panel.js` → `apply()` | пишет параметры в URL, сетку не трогает | то же |
| табы каруселей | `components/carousel.js` → `initTabs()` | фильтрует массив по полю `tab` | `GET {endpoint}?tab=…` |
| добавление в корзину | `components/cart.js` → `addToCart()` | счётчик в шапке через localStorage | `POST /cart` с `data-product-id` |
| количество в заказе | `components/order-cart.js` → `commit()` | пересчитывает итог на клиенте | `PATCH /cart` со всеми строками, сервер возвращает количества и итог |
| комплектация строки заказа | `components/order-modules.js` → `commit(line)` | пересчитывает цену кухни как сумму модулей | `PATCH /cart/{line}/modules` |
| поиск | `components/search.js` → `searchSuggest()` | ищет по локальному массиву; сабмит формы перехвачен, потому что страницы `/search` нет | `GET /search/suggest?q=…`; обработчик сабмита удалить, форма уйдёт обычным GET |
| формы модальных окон | `components/modals.js` → `SEAMS` | шесть функций-заглушек по имени окна; «Доступ к оптовым ценам» зовёт шов входа — это то же окно под другим заголовком | `POST` с `FormData(form)` и CSRF-токеном |
| прайс-лист дилера | `components/price-mode.js` → `applyPriceMode()` | localStorage + пересчёт `[data-price-base]` на клиенте | смена прайс-листа на сервере, цены приходят готовыми |
| город | `components/city-select.js` → `setCity()` | localStorage, правит все `[data-city-label]` | запрос; список салонов приходит уже отфильтрованным |

Об одном шве стоит знать заранее: **у прайс-листа три режима, и «Показать
цену» — не фильтр, а тумблер применения** этого режима. Выключен — везде
оптовая цена, включён — выбранный режим («Оптовая / Рекомендованная / Своя
наценка», у последней поле `%` с минимумом 50; коэффициент РРЦ — заглушка
`RRP_FACTOR` в `data/dealer-home.js`, откуда берётся реальная РРЦ — вопрос в
BACKLOG). Каждая цена в разметке несёт `data-price-raw` / `data-price-base` —
их ставят `product-card.js`, `catalog-listing.js` и `pdp.js` (сводка и нижние
бары), — и пересчёт идёт от них. На сервере это просто разные цены в выдаче,
а на `<body>` остаётся `data-price-mode` для стилей.

| `data/certificates.js`, `data/schemes.js`, `data/tech-info.js` | деревья документов (глубина 1 / 4 / 3) |
| `data/decors.js`, `data/models.js` | карточки декоров и 3D-моделей |
| `data/learning.js` | восемь видеокарточек |
| `data/constructor.js` | адрес встроенного приложения o3d.ru — в Blade собирается сервером вместе с сеансом |

В шапке каждого файла написано, во что он превращается на сервере и какие поля
обязательны. Форма записи товара:

```js
{ id, image, title, price, oldPrice?, badges?, swatches?, more?, comments?,
  category?, tab? }
```

Три замечания, чтобы не потерять время:

* **`data/asset-base.js` — единственное место, где задаётся путь к медиа.**
  Меняете одну строку — переезжают все моки. Пути относительные, потому что
  прототип должен открываться и как папка, и с dev-сервера; на сервере это
  станет `asset(...)`.
* **`data/product-photos.js` — костыль прототипа, а не данные.** В фикстурах у
  товара одна картинка, а галерея карточки показывает три кадра, поэтому
  `demoGallery()` добирает соседние фото той же категории. На сервере у модели
  есть свои `images`: файл удаляется, а `buildCard()` идёт по ветке `p.images`,
  которая там уже написана.
* **Заголовки и описания секций — не моки.** Они лежат в разметке страницы или в
  её скрипте (`pages/*/*.js`) и являются частью дизайна: это реальный текст из
  макета, а не заглушка. Переносите как есть.

## 7. CSS: как не сломать вёрстку в первый же день

`styles/app.css` — это **скомпилированный** Tailwind v4. Tailwind генерирует
только те классы, которые нашёл, **просканировав исходники**.

Отсюда главная ловушка переноса:

> Вы добавляете в `.blade.php` класс, которого не было в прототипе (например
> `mt-7`) — и он не работает. Не потому что вёрстка сломалась, а потому что
> этого класса нет в скомпилированном файле.

Правильно — подключить Tailwind к сборке проекта и пересобирать CSS по
Blade-шаблонам:

```bash
npx @tailwindcss/cli -i resources/css/app.css -o public/css/app.css --watch
```

Где `resources/css/app.css` — перенесённый `src/styles/app.css` из репозитория
вёрстки (исходник с `@import "tailwindcss"` и блоком `@theme`, а не
скомпилированный файл из этой папки).

Ещё два правила из того же файла:

* **Токены дизайн-системы живут в `@theme`** и являются единственным источником
  правды: `bg-surface-accent-alt`, а не `bg-[#4a9b7d]`. Цвета, шрифты, радиусы и
  тени уже заданы там по макету.
* **Свой класс, который используется с вариантом** (например
  `max-md:scroll-rail`), обязан быть объявлен через `@utility`, а не в
  `@layer components`. Иначе Tailwind молча не сгенерирует вариант — без ошибки,
  просто не будет стиля.

## 8. Состояния — это `data`-атрибуты, а не отдельные страницы

В Figma несколько состояний одного экрана нарисованы отдельными фреймами. В
вёрстке это один шаблон с атрибутом-переключателем, а различия выражены через
`group-data-[…]` прямо в классах:

| Атрибут | Где | Значения |
|---|---|---|
| `data-user` | `<body>` любой страницы | `dealer` или отсутствует — дилерская шапка, подвал, «Бизнесу» в тапбаре, цены без «от», сводка PDP без скидки |
| `data-step` | страница заказа покупателя | `0` / `1` / `2` — три шага |
| `data-delivery` | карточка «Доставка» дилерского заказа | `pickup` / `delivery` — тело карточки 264 → 616 |
| `data-count` | строка корзины | `one` — при количестве 1 степпер рисует корзину вместо минуса |
| `data-state` | оверлей поиска | `empty` / `query` |
| `data-mode` | ящик фильтров | `single` / `all` — один раздел фильтра или все |
| `data-audience` | `<body>` Контактов | `opt` / `retail` — склад или розничная сеть в панели карты |
| `data-pages` | пагинация | число страниц — прячет то, что не влезает |
| `data-empty` | сетка каталога | `true` — пустая выдача |
| `aria-selected`, `aria-current` | чипсы, табы, пины карты, пункт тапбара, пункт `menu-b2b` | активность |

Важная особенность заказа покупателя: **на десктопе шаги накапливаются, на
мобильном заменяют друг друга.** Поэтому каждая секция несёт два правила —
`hidden` («шаг ещё не наступил») и `max-md:hidden` («сейчас показан другой
шаг»). Это не дублирование, а два разных условия. У дилерского заказа шагов
нет — там одна страница в двух состояниях доставки.

Поиск и модальные окна — не страницы, а оверлеи, которые несёт каждая
страница (`partials/search-overlay.html`, `partials/modals.html`). У окон одна
оболочка в `app.css` — `.modal-scrim` + `.modal-panel`: карточка 485 по центру
выше `md` и шторка снизу ниже. Открытое окно — это класс `is-open` на подложке,
всё остальное делает CSS.

## 8а. Микроразметка schema.org

Каждая страница несёт два блока JSON-LD в `<head>`, и оба надо перевести на
серверные адреса — сейчас домен в них написан буквально.

**Organization** — `partials/schema-org.html`, одинаковый на всех страницах,
подключается обычным `@include('partials.schema-org')`. Внутри четыре поля
(`name`, `url`, `logo`, `telephone`) — состав задан SEO-специалистом
заказчика. `https://mebel.com` в `url` заменяется на `url()`. `logo` уже
указывает на файл живого сайта (`/img/logo.svg`, тот же, что стоит в шапке и
подвале с 18.09) — в Blade это `asset('img/logo.svg')`, если файл переедет,
а в прототипе он лежит как `assets/header/logo.svg`.

**BreadcrumbList** — свой блок в каждой странице, кроме главной (у покупателя и
у дилера главная одна и та же). Партиалом он не сделан намеренно: содержимое у
каждой страницы своё, поэтому в Blade это
`@include('partials.schema-breadcrumbs', ['items' => [...]])` с массивом звеньев.
Адреса звеньев в вёрстке — имена файлов (`https://mebel.com/catalog.html`);
подставьте `route()`. У последнего звена адреса нет и не должно быть — это
текущая страница.

Где крошки видны на экране (оба каталога, обе PDP, страница модуля, Акции,
3D-модели), **разметка обязана повторять их слово в слово** — так требует
Google. Меняете текст крошки — меняйте и JSON. В репозитории вёрстки это
стережёт `npm run schema`.

**Одна засада при слиянии половин.** Дилерская и покупательская PDP в бою — один
маршрут, а крошки у них в макете разные: у покупателя четыре звена, у дилера три.
Выберите одну цепочку и спросите дизайнера, какая верна (вопрос записан в
BACKLOG вёрстки). У каталога и заказа цепочки совпадают, там выбирать нечего.

Тринадцать страниц крошек не рисуют (макет их там не предусматривает), но
разметку несут: цепочка «Главная › имя страницы».

## 9. Кто смотрит страницу — сеанс, а не разметка

Раздел «Для бизнеса» один на обе половины: по словам клиента, «страницы
шарятся, плашка меняется в зависимости от логина дилера». В прототипе это
выражено так:

* собственные экраны дилера (главная, каталог, PDP, заказ, конструктор) держат
  `data-user="dealer"` на `<body>` жёстко;
* одиннадцать контентных страниц раздела читают его из `localStorage` —
  `partials/session.html`, встроенный синхронный скрипт сразу после `<body>`
  (отложенный модуль дал бы шапке отрисоваться покупательской и мигнуть);
* `components/session.js` держит флаг: окно «Войти в режим дилера» его ставит,
  «Выход» в дилерской полоске и в бургере снимает.

Роль решает и **адрес**. Общая обвязка лежит в одних партиалах, а её ссылки
относительные, и с контентной страницы `main.html` разрешался бы в дилерскую
главную кому угодно. Поэтому такие ссылки написаны в разметке полным путём в
покупательскую половину и помечены `data-half`; для дилера сегмент подменяет
`initSession()`. Адреса, которые собираются из данных (меню каталога, рубрика
под карточкой), идут через `pageHref()` в `components/links.js`.

**В Blade всё это исчезает.** Сервер рендерит `data-user` прямо в `<body>` по
сеансу, `route()` собирает адреса по той же роли; `session.html`, `session.js`,
`links.js` и `data-half` не переносятся. Подробно — `docs/LINK-MAP.md` в
репозитории вёрстки, разделы 0 и 6.

Отсюда же **правило для двух пар страниц**, каталога и PDP: у них должен быть
один шаблон, а не два, — все различия дилерского варианта уже выражены
правилами `group-data-[user=dealer]:…` (их 86) и одним переключателем в
`catalog-settings` («Только модули»). Собирать дилерский `catalog.blade.php`
отдельно от покупательского не нужно.

## 10. Что дизайном не закрыто

Это не недоделки вёрстки — это места, где макета нет. Полный список с датами и
решениями клиента — `BACKLOG.md` в репозитории вёрстки; здесь то, во что перенос
упрётся первым:

* **Категории мега-меню, кроме «Кухни»** — в Figma детально нарисована только
  она, у остальных восьми нет подкатегорий и коллекций. Механика рендера их уже
  поддерживает: появятся данные — появятся колонки.
* **Четыре пункта меню «Для бизнеса» без страниц** — Поставщикам,
  Прайс-листы, Каталог мебели, Методические пособия: в макете у них нет
  фреймов, в `data/menu-b2b.js` они стоят с `href="#"`.
* **Варианты оплаты в дилерском заказе** — селект есть, его пункты дизайн не
  называет.
* **Крошки дилерской PDP** — три звена против четырёх у покупателя (раздел 8а).
* **Иконка MAX** в окне «Поделиться» и в подвале — у мессенджера нет
  документированного share-адреса, стоит `#`.
* Блок салонов на десктопе называется **«Где купить»**, на мобильном макете —
  «Наши салоны». Использовано «Где купить» на обеих ширинах: мобильный фрейм
  переопределяет только описание, но не заголовок, что читается как
  непереименованный компонент, а не как решение.
* **Конструктор мебели** — страницы в макете нет вовсе; всё, что на ней есть,
  придумано по заказу клиента и записано в BACKLOG.

Уточняйте у дизайнера, не додумывайте.

## 11. Если нужно пересобрать эту папку

Она собирается из репозитория вёрстки:

```bash
npm run build:php     # → dist-php/   эта папка
npm run build         # → dist/       самодостаточные HTML для показа заказчику
```

Вторая сборка — только для демонстрации: там всё сжато и вклеено в один файл,
для переноса она не годится.
