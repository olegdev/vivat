## Что строим

`src/pages/dealer/catalog.html` + `catalog.js` — дилерская страница каталога на
обеих ширинах.

Обход деревьев показал: дилерский фрейм — покупательский каталог нода в ноду.
Тот же `products` из `cards-kitchen size=m` (322×389, 4 колонки на 1440;
168×259, 2 колонки на 360), та же пагинация, тот же блок H2 «Популярные товары»
(`title-block` + `segments` + `other-row`, инстансы совпадают с покупательскими
до id мастера), та же зелёная SEO-полоса (`Frame 2087325443`, у обеих 1650:87849
/ 759:60484). H1 — «Кухни VIVAT», как у покупателя: у инстанса нет ни одного
текстового переопределения, значит копия наследуется от мастера.

Отличий по существу четыре:

| | покупатель | дилер |
|---|---|---|
| шапка / подвал / нижняя навигация | customer | dealer (`data-user="dealer"`, готово) |
| `catalog-settings` | `type=customer` (768:28896 / 1806:237126) | `type=dealer` (880:17203 / 1806:238139) — **плюс тумблер «Только модули»** |
| цена в карточке | «от 81 705₽» | без «от», пересчёт по выбранному прайс-листу |
| 360: хлебные крошки + H1 | есть | **нет** — так нарисовано |

Модалка фильтров (`partials/catalog-filters.html`) переиспользуется как есть, на
обеих ширинах.

## Архитектура: тело каталога уезжает в партиалы

Сейчас панель настроек, шаблон карточки, сетка и пагинация лежат инлайном в
`src/pages/customer/catalog.html` (~250 строк), а вся механика — в
`src/pages/customer/catalog.js` (423 строки). Вторая страница с той же
механикой означала бы вторую копию всего этого, включая шаблон карточки — на
чём проект уже обжигался (см. BACKLOG › два шаблона `cards-other size=s`).

Разбираем на партиалы, обе страницы собираются из них:

```
src/partials/catalog-settings.html   воронка + 6 таблеток + «Только модули» + сортировка + ряд чипсов
src/partials/catalog-grid.html       <template> карточки + [data-grid] + пустое состояние
src/partials/pagination.html         «Показать ещё …» + нумерация
src/components/catalog-listing.js    фильтры, сортировка, чипсы, таблетки, URL, шов applyFilters
```

Правило «один партиал == один будущий Blade-партиал» соблюдено: панель
настроек в Figma и есть один компонент `catalog-settings` с вариантом
`type=dealer`, поэтому дилерская добавка живёт в нём одном под
`group-data-[user=dealer]`.

`catalog-listing.js` экспортирует одну функцию:

```js
initCatalogListing({ products })   // сетка + фильтры + сортировка + чипсы + URL
```

Обе страничные `catalog.js` после этого — чистая обвязка: инициализация шапки,
меню, поиска, корзины, вызов `initCatalogListing` и монтирование карусели
«Популярные».

## Тумблер «Только модули»

Figma: `text+toggle` [882:89379](https://www.figma.com/design/locvXJpmVZqIMVwPoumae3/VIVAT?node-id=882-89379)
(1440) и [1806:238263](https://www.figma.com/design/locvXJpmVZqIMVwPoumae3/VIVAT?node-id=1806-238263) (360).
Один DOM, две раскладки по брейкпоинту.

**1440.** Строка `filters` 1360 остаётся `justify-between`. Правая группа —
`popular` 480 = текст+тумблер 168 → gap 32 → сортировка 280. Текст 116×22
(`body-n`), тумблер 40×24 с зазором 12.

**360.** Панель вырастает 116 → 164. Блок `filters` становится колонкой 328×96
с зазором 8:

- строка 1 (328×44): воронка 44 слева, текст+тумблер 154 справа —
  `justify-between`; текст 102×20 (`m-body-n`), зазор 12;
- строка 2: сортировка на всю ширину 328 (у покупателя она 240 и стоит в одной
  строке с воронкой).

Ряд чипсов ниже — без изменений.

Разметка тумблера — та же, что у «Показать цену» в `partials/header.html`
(кнопка с `aria-checked`, `group/sw`, дорожка 40×24, шарик 20 со сдвигом 16).
Виден только дилеру: `group-data-[user=dealer]`.

**Поведение** — поле того же шва. `readState()` читает `modules_only`,
`matches()` отсеивает товары без флага, `toParams()` кладёт `modules_only=1` в
строку запроса, `hydrateFromURL()` восстанавливает. Переключение применяется
сразу, как быстрые чипсы. Прототипа у тумблера в макете нет — решение
записываем в BACKLOG.

В фикстуры `src/data/catalog.js` добавляется поле `isModule` (данные, не
выдумка дизайна), иначе фильтр нечем показать.

## Цены

`buildCard()` начинает проставлять `data-price-base` на `[data-card-price]` —
сейчас это делает только `components/product-card.js` для рельсов, а сетка
каталога строится своим шаблоном. После этого `initDealerPriceControls()`
пересчитывает карточки сетки тем же `applyPriceMode()`, что и главную; новой
логики нет.

Приставка «от» гасится в шаблоне сетки так же, как в `partials/product-card.html`:
`group-data-[user=dealer]:hidden`.

Фикстуры дилер берёт покупательские (`src/data/catalog.js`) — товары те же,
отличается только показ цены. Нового файла данных не будет.

## Дилерская обвязка страницы

`src/pages/dealer/catalog.html` повторяет обвязку `dealer/main.html`:
`<body class="group …" data-user="dealer">`, инклюды `header`, `catalog-menu`,
`mobile-menu`, `search-overlay`, `price-mode`, `bottom-nav`, `footer`,
`catalog-filters`; скрипт вызывает `initDealerPriceControls()` и передаёт
`dealerMenuSections` в `initMobileMenu`.

Ниже `md` хлебных крошек и H1 нет — блок обёрнут в `max-md:hidden`.

`src/index.html` — руками добавить строку про новую страницу.
